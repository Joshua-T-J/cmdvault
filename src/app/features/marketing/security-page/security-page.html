Straight talk

Your vault is a secret gist, which is unlisted, not private. Anyone with its URL can read it. CmdVault is a good home for commands, not for passwords or API keys — and it actively stops you from saving them by accident.

How data flows

Your browser → HTTPS → api.github.com → your secret gist
  • There is no CmdVault server or database. The site is static files.
  • Every request to GitHub is made from your browser over HTTPS.
  • The app only makes network requests to api.github.com and, for very large vaults, gist.githubusercontent.com.
  • CmdVault only ever writes to its own vault gist — never to your other gists.

Your GitHub token

What it can do

GitHub can’t limit a token to a single gist. A token with Gists access can read, create, edit and delete all of your gists. Set it up narrowly:

  • Use a fine-grained token.
  • Repository access: No repositories.
  • Account permissions: Gists — Read and write, nothing else.
  • Expiry: 90 days or less.
  • Classic token instead? Tick only the gist scope. CmdVault warns you if it finds more.

How CmdVault keeps it

  • In memory by default. Reloading the page forgets it; a password manager makes re-pasting quick.
  • Remember for this tab is opt-in and uses session storage, which is cleared when the tab closes.
  • Never in local storage, never in cookies, never in the URL.
  • The token is attached only to requests whose origin is exactly api.github.com.
  • The token field is cleared as soon as verification succeeds, and tokens are stripped from any error logs.

The secret check

Before a command is saved, CmdVault scans it for things that look like credentials. If it finds one, Save stays disabled and the match is highlighted. One click replaces it with {{ '{{' }}API_KEY{{ '}}' }}, which you fill in at copy time and which is never stored. Imported files are scanned too: anything that looks like a secret is replaced with {{ '{{' }}API_KEY{{ '}}' }} before it reaches your gist.

The check runs entirely in your browser. It can’t catch every possible secret, so treat it as a safety net, not a guarantee.

Input validation

Everything you type, import or load from your gist is treated as untrusted text. Angular escapes it whenever it is shown, and CmdVault never renders it as HTML. On top of that:

  • Titles, notes and tags reject HTML tags, javascript: links and inline event handlers. Doc-style placeholders such as <branch> are fine.
  • Tags may only use letters, numbers and . _ + # -.
  • Hidden characters — right-to-left overrides, zero-width spaces and control characters — are blocked in the editor, because they can make a command run something different from what you see. One click removes them.
  • Placeholder values can’t contain line breaks or hidden characters, so filling one in can’t sneak an extra command into what you paste into a terminal.
  • Imports and the gist itself are cleaned when loaded: markup and hidden characters are stripped, lengths are capped and unsafe tags are dropped.
  • The source code is checked on every build for APIs that bypass Angular’s protection (such as innerHTML or bypassSecurityTrust) and for hidden characters.

Saving and sync

  • Changes are saved about 1.5 seconds after you stop editing.
  • Before each save, CmdVault fetches the latest vault and merges it command by command.
  • If the same command changed on two devices, the newer edit wins and the other is kept as a “conflicted copy” — nothing is silently lost.
  • Only one browser tab saves at a time, and other tabs refresh when it finishes.
  • Deletes are remembered for 30 days so a stale device can’t bring a command back.

Browser protections

  • Commands are always rendered as plain text — never as HTML — so a saved command can’t run script.
  • A strict Content Security Policy with Trusted Types limits scripts to our own files and network requests to GitHub. It is being rolled out in report-only mode first, then enforced.
  • No third-party scripts, analytics or CDNs; fonts are self-hosted.
  • The site can’t be embedded in other sites’ frames (clickjacking protection).
  • HTTPS is enforced with HSTS, plus nosniff and a strict referrer policy.
  • Your vault pages are marked noindex so search engines never list them.

Encryption

Coming soon. Optional end-to-end encryption will let you lock the vault with a passphrase so that anyone with the gist link sees only ciphertext. The key will be derived in your browser (PBKDF2-SHA256, 600,000 iterations) and used with AES-GCM-256 via Web Crypto. It will never leave your device.

Until then, assume anyone with your gist’s link can read every command in it.

What we can’t protect

  • Someone who has your gist link can read the vault.
  • A compromised computer or malicious browser extension can read anything on the page, including the token while the tab is open.
  • A compromised GitHub account exposes the gist and lets an attacker create new tokens.
  • Gist history keeps earlier versions — removing a secret later doesn’t erase it from history.
  • GitHub itself can access gists it hosts.

Best practices

  • Use a fine-grained token with Gists access only and a short expiry.
  • Turn on two-factor authentication for your GitHub account.
  • Keep real secrets in a password manager, not in commands — use placeholders.
  • Don’t tick “Remember for this tab” on shared or public computers.
  • Sign out when you’re done on a shared machine.
  • For extra separation, use a dedicated GitHub account just for CmdVault.

If your token leaks

  1. Revoke it right away: fine-grained tokens or classic tokens.
  2. Check your gists for anything unexpected at gist.github.com.
  3. Review your account’s security log.
  4. Create a new token and reconnect CmdVault.

If a secret was ever saved in your vault, rotate that secret too — it remains in the gist’s revision history.

Report a vulnerability

Found a security problem? Please don’t open a public issue. Report it privately through GitHub’s private vulnerability reporting instead. Include the steps to reproduce, what an attacker could do, and the browser you used.

We aim to acknowledge reports within a few days, keep you updated while we fix the problem, and credit you in the release notes if you’d like.
